Case Study

프로세스가 실제로 작동한 기록 — 경기도 문화시설 접근성 분석

"어디에 지을 것인가"를 "왜 기존 배치는 실패하는가"로 바꾸자, 정책이 움직였다

경기청년 연구랩업 (경기도미래세대재단) · 2025.05 – 2025.10 · 3인 팀 팀장

대상 수상 공공데이터 50만+ 건 분석 정밀도 +25% 취약 지역 5곳 도출 경기도 정책 실무 검토

01 · 문제 재정의

주어진 질문을 의심했다

과제는 "청년 문화시설을 어디에 지을 것인가"였습니다. 하지만 기존 배치가 이미 거리 기준으로 이뤄져 왔는데도 격차가 남아 있다면, 질문이 잘못된 것입니다. 팀이 채택했던 거리 기반 방법론의 허점 — 대중교통 배차와 실질 이동 시간을 반영하지 못한다는 점 — 을 먼저 제기하고, 문제를 "왜 거리 기반 배치는 실패하는가"로 다시 세웠습니다.

02 · 데이터로 현실 확인

31개 시·군, 1,440개 행정동, 50만 건

인구통계·문화시설 API·대중교통 노선과 배차 간격까지 공공데이터 50만 건 이상을 통합했습니다. 출처마다 좌표 체계와 형식이 달라 분석이 중단되자, 팀원들의 수작업 변환 대신 pandas·geopandas로 형식을 자동 표준화하는 전처리 파이프라인을 직접 구축했습니다. 10여 종 데이터를 12개 카테고리로 세분화하고 변수별 조작적 정의를 담은 분석 매뉴얼을 만들어 팀원 간 해석 오류를 없앴습니다.

03 · 지표 설계

'문화 접근성 지표'를 직접 정의했다

단순 직선거리 대신 2SFCA 방법론에 배차 간격·도보 거리 변수를 반영한 접근성 지표를 설계 — 분석 정밀도가 25% 올랐습니다. Moran's I·LISA·K-means로 소외 패턴을 정량화하고, AHP·TOPSIS로 취약 지역 5곳과 최적 입지를 도출했습니다.

04 · 이해관계자 정렬

이틀 평행선이던 갈등, 30분 만에 합의

중반에 '공공 부지 중심'과 '역세권 실질 수요 중심'으로 분석 방향이 갈렸습니다. 다수결 대신 1:1 면담을 했고, 이견의 본질이 방법론이 아니라 정보 불투명과 신뢰 부족임을 확인했습니다. 양쪽 결과물을 같은 기준으로 시각화해 나란히 놓고, 두 지표를 가중치로 통합한 '입지 적합성 모델'을 제안 — 각자의 기여가 모델에 반영된 것을 눈으로 확인하자 30분 만에 합의됐습니다.

마감 직전 위기: 데이터 소스 간 측정 단위 불일치로 분석 결과 전체 폐기 위기. 포기 대신 1만 건 DB를 전수 조사해 오류 150건을 수정하고 프로젝트를 살렸습니다. 이후 단계별 전처리 검증 로그 작성을 의무화 — 동일 유형 오류 재발 0건.

05 · 실행 가능한 산출물

분석 보고서가 아니라, 판단 근거를 전달했다

수치 나열 대신 시설 1개소당 예산 대비 사회적 가치까지 산출해, 담당자가 즉시 판단 근거로 쓸 수 있는 실행 로드맵으로 재구성했습니다. 결과는 대상 수상, 그리고 경기도 정책 반영 실무 검토 — 분석이 "무엇이 문제인가"를 밝히는 일이라면, 기획은 "왜 이 해법이며 어떻게 실행할 것인가"를 설계하는 일임을 확인한 프로젝트입니다.

How I Work

두 가지 장면

① 위기를 버티게 하는 것 — 평소의 구조화

셀렉트스타 납품 하루 전, 거래처 데이터 규격이 예고 없이 전면 변경돼 1,000건이 처리 불가 상태가 됐습니다. 주니어였지만 긴급 회의를 먼저 제안했고, 평소 학습해 둔 데이터 구조·매핑 지식으로 신·구 형식 차이를 자동 식별·재매핑하는 방식을 설계했습니다. 역할을 나눠 이중 검증하며 당일 전량 납품 — 평소의 오류 유형화와 파이프라인 투자가 위기 대응력이 된 순간이었습니다.

빠른 수정으로 오류를 가리는 것과, 재발하지 않는 체계를 설계하는 것은 전혀 다른 방향의 일입니다.

② 반복을 데이터로 바꾸는 습관 — 현장에서 배운 것

전통시장 매장에서 5개월간 일평균 200명을 응대하며, 월 15건씩 반복되는 클레임에 처리 기준이 없다는 문제를 발견했습니다. 클레임을 상품 불량·가격 오해·서비스 불만 3유형으로 분류해 응대 기준을 만들고, 클레임이 잦은 상품군의 진열 위치 조정까지 제안해 문의 자체를 줄였습니다. 이 습관은 셀렉트스타의 오류 3유형 구조화로 그대로 이어졌습니다.

반복은 처리 대상이 아니라, 발견하고 정의해야 구조가 보입니다. 이 사실을 저는 이론이 아닌 현장에서 익혔습니다.
