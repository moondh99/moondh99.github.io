문제 발견의 근거

보호자는 질문과 사진을 준비하고 시니어를 초대하며 결과를 검토한다. 시니어는 초대 링크로 들어와 음성으로 답한다. 팀은 서로 다른 두 사용자의 할 일을 나눠, 준비부터 인터뷰·검토·PDF 제작까지 이어지는 흐름을 설계했다.

데모 검토 유형에는 글자 잘림·줄바꿈, 동의 설정, 모바일 UI가 포함됐다. 발견한 문제를 후속 작업으로 이어 갈 수 있도록 남겨야 했다.

선택과 이유

발견한 문제를 수정 요청으로 정리해 화면을 만든 팀이 후속 작업을 이어 갈 수 있도록 했다.

본인 행동과 협업

백엔드 연결과 에이전트 흐름을 다루는 한편, 데모 화면의 수정 사항을 정리했다. 6월 7일 변경 기록에는 본인 명의 검토 항목 10건과 팀 완료 표시가 남아 있다.

확인한 결과와 검증

개인 검토 항목과 팀 완료 기록을 연결하면 발견 화면·수정 요청 → 팀 완료 기록의 변화 과정을 보여줄 수 있다. 텍스트 잘림·동의 설정·모바일의 수정 전 캡처 3건도 근거 자료로 남아 있다.

팀 결과보고서에는 구성안·본문 집필·인터뷰 원본 대조의 3단계 AI 파이프라인과 비동기 큐가 기술되어 있다. 현재 공개 소개 화면 접근은 확인됐으며, 전체 기능 흐름과 실제 이용 효과는 후속 검증 범위다.

한계와 다음 확인

10건은 본인 명의 검토 요청 수다. 본인의 직접 해결 건수나 사용자 수로 해석하지 않는다.

수정 전 캡처 3건은 확인됐으나 촬영 주체는 미확정이며, 같은 화면의 수정 후 캡처는 확보되지 않았다. 항목별 개인 구현·담당 범위도 보완이 필요하다.

동의 5종은 현재 팀 자료다. 학기 개인 설계 실적으로 소급하지 않는다. 캡스톤 대상은 수상 원본 대조가 남아 있어 확정 성과로 강조하지 않는다.

SMS 연결·앱 배포·전체 기능의 동작과 실제 이용 효과는 후속 검증 범위이며, 유산 금고는 데모 범위다. 7~9월 후속 구현·검토는 AI 협업으로 학기 활동과 구분한다.
