01 — 무엇이 문제였나

물어보려던 이야기는 말로만 남음

부모님의 인생 이야기는 대부분 말로만 남아 있다가 사라짐. 자녀는 언젠가 물어봐야지 하면서도 막상 마주 앉아 정식으로 인터뷰하기는 어색함.

그래서 팀은 흐름을 역할별로 분리. 자녀(보호자)가 질문과 사진을 준비하고, 부모님은 음성이나 글로 답변. AI가 받아 적고 다듬은 내용을 가족이 원문과 대조해 검토한 뒤 장에 추가. 마지막 산출물은 A5 자서전 PDF.

학기 중 본인 담당은 이 흐름에서 프런트엔드를 로컬 API와 SQLite 백엔드에 잇고, 사진과 가족 질문, 자서전 데이터를 DB에 연결하는 일.

02 — 학기 중 한 일

데모를 직접 써 보고, 수정 요청 10건

6월에 개발 총괄로 배정된 뒤, 데모를 부모님 화면과 자녀 화면 양쪽에서 직접 사용. 걸리는 곳마다 화면 캡처와 바꿀 내용을 붙여 요청 10건을 팀 문서에 작성(2026.06.07 기준).

  • 부모님 화면과 자녀 화면 모두의 글자 잘림, 줄바꿈
  • 동의 설정 화면 수정, 개발자 설정 숨기기
  • 부모님 화면의 ‘사진 보고 이야기하기’와 ‘질문에 답하기’가 같은 화면으로 열리는 문제
  • 인터뷰 캘린더를 더 잘 보이는 곳으로
  • 부모님 화면을 모바일에 맞게
  • 고정된 책 표지, 실제 페이지 수 표시

팀 문서에는 10건 모두 완료로 표시되어 있다. 이는 요청의 처리 상태이며, 10건 전부를 본인이 구현하거나 같은 버전에서 재검증했다는 뜻은 아니다. 아래 화면은 서비스 흐름을 보여 주는 후속 데모 캡처로, 수정 전후 비교 자료와 구분했다.

03 — 무엇을 결정했나

학기 후, 공개해도 되는 범위부터 결정

7월부터는 팀 과제와 별개로 개인 작업을 이어 갔다. 공개 범위와 동의 적용, 운영 정책은 본인이 판단하고 구현은 AI와 협업했다.

  • 공개 범위10월 9일에는 샘플·문의부터당시 신규 가입·기록 입력을 제한했다. 10월 22일 코드에는 별도 회원가입 진입이 추가되어, 이 결정을 현재 가입 상태로 일반화하지 않는다.
  • 서버데모 서버와 운영 서버를 분리가상 가족 데이터로 도는 데모가 실제 운영 데이터와 섞이지 않도록 분리.
  • 동의동의 5종이 실제로 적용되게답변마다 고른 동의가 이미 만든 책까지 반영되도록 처리하고, 과하게 막던 부분은 다시 해제.
  • 로그인로그인 코드는 SMS 대신 이메일SMS 발송 업체를 아직 정하지 않았기 때문.

05 — 무엇이 남았나

공개 소개와 고객 서비스 출시를 구분

팀 데모의 수정 요청과 완료 기록, 음성 인터뷰부터 가족 검토·자서전까지의 화면, 후속 개인 작업으로 만든 공개 소개·샘플이 남았다.

2026.10.22 로컬 코드
소개 페이지에 가상 예시·사전신청·회원가입·문의 진입을 제공한다. 회원가입은 별도 계정 페이지로 연결된다.
핵심 기능의 안내
같은 코드의 FAQ는 질문 보내기·음성 답변·자서전 기능이 아직 열리지 않았다고 안내한다. 가입 진입과 실제 서비스 이용 가능 여부를 구분했다.
성과로 주장하지 않은 것
이 상태는 로컬 코드 확인 결과다. 공개 사이트의 최신 배포·가입 완료와 실제 고객 운영, 이용자 수·매출은 이번에 검증하지 않았다.

학기 중 화면·문서는 팀 작업. 이후 공개 범위와 운영 정책 결정은 본인, 구현은 AI 협업. 실제 화면에 보이는 가상 데이터를 고객 성과로 환산하지 않았다.

06 — 배운 점

이 사례에서 배운 것

직접 써 봐야 고칠 곳이 보인다는 점 확인. 부모님 화면과 자녀 화면을 각각 써 보며 캡처와 바꿀 내용을 붙여 적으니 팀이 바로 처리할 수 있는 요청이 됨.

공개 범위는 개발 진척에 맞춰 다시 정해야 한다. 10월 초에는 샘플과 문의로 범위를 제한했고, 이후 코드에는 가입 진입을 추가했다. 두 시점의 결정을 구분해 기록해야 소개 페이지와 실제 이용 가능 기능이 어긋나지 않는다.
