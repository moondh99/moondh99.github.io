01 · 문제와 범위

할 일 목록을 실제 시간표로 옮기는 과정

회의가 많고 할 일이 여러 곳에 흩어진 직장인과 프리랜서를 대상으로 삼음. 메모를 정리하는 것에서 멈추지 않고 고정 일정, 소요 시간, 마감, 우선순위를 함께 반영하는 흐름을 설계.

사용자는 메모를 입력하고 에이전트 진행 과정을 본 뒤 시간표와 배치 이유를 검토. 캘린더 파일(.ics)은 확인 버튼을 누른 뒤에만 내려받을 수 있음.

아침 계획에 15~20분이 든다는 수치는 기획 가정. 사용자 비교 실험을 하지 않았으므로 시간 절감 성과로 제시하지 않음.

02 · 에이전트와 코드의 경계

AI가 짠 시간표를 코드로 다시 검사

정리, 시간 추정, 우선순위, 배치, 위험 점검, 코칭을 6개 에이전트가 나눠 맡음. 시간 추정과 우선순위 작업은 병렬로 실행하고, 날짜 해석·빈 시간 계산·일정 검증·파일 내보내기는 별도 MCP 도구로 분리.

계산

날짜·시간 계산과 규칙 검사는 코드

모델의 시간 계산을 그대로 믿지 않고 일정 겹침, 근무 시간, 여유 시간, 업무 부하 등을 검사하도록 분리.

권한

내보내기 도구는 에이전트에게 주지 않음

사용자 확인 값이 없는 요청은 서버가 거부. 에이전트의 일정 제안이 캘린더 내보내기로 곧바로 이어지지 않게 함.

표시

실제 AI 실행과 기록 재생을 구분

기록된 실행은 AI 호출이 없다는 라벨을 표시. 재생 결과를 새로운 AI 실행인 것처럼 보여 주지 않음.

기술: .NET 10 · Microsoft Agent Framework · GitHub Copilot SDK · MCP · Aspire · Azure Container Apps.

03 · 작업 방식

구현 전에 문서와 확인 조건을 정함

작업 규칙, PRD, TRD, 설계 결정 기록을 먼저 두고 모델·에이전트·지침·도구를 분리. 사람은 방향 설정과 승인을, AI는 조사·구현·문서·검증을 맡는 방식으로 진행.

배포를 일찍 시도해 Azure 환경 모드 문제를 확인하고 설정을 명시하도록 변경. 실제 화면 점검에서 병렬 도구 호출의 결과가 다른 줄에 붙는 문제와 중지 배너 표시 문제를 찾아 제출 커밋에서 수정.

문대한은 행사 등록 이슈의 팀 리더. 팀원별 구현 분담을 증명하는 기록은 없어 위 작업을 개인 단독 성과로 구분하지 않음.

04 · 제출본과 후속 개선

수상 제출본과 이후 고도화를 구분

최종 제출 · 9222bc0

2026.11.05 제출 이슈 #148에 등록된 커밋. 6개 에이전트, MCP 계산·검증, 실시간 타임라인, 사용자 확인 후 내보내기를 포함.

제출본 README에는 Azure 실제 AI 실행 39.4초가 기록됨. 특정 입력의 실행 기록이며 평균 성능이나 시간 절감 효과를 뜻하지 않음.

후속 고도화 · 823c063 이후

무효한 시간표는 완료 처리하지 않는 조건, 이전 유효 계획 복원, 배치 변화와 소요 시간 출처 표시 등을 보강.

고도화는 제출 커밋에 포함되지 않았고 마감 뒤 재배포됨. 심사가 어느 배포 버전을 확인했는지는 기록만으로 확정할 수 없음.

수상 근거와 제출 커밋을 별도로 연결해 수상 사실이 후속 기능의 검증 근거로 읽히지 않도록 함.

05 · 결과와 현재 상태

최우수상, 그리고 공개 데모의 한계

2026 청도 바이브코딩 해커톤 최우수상. 수상 보도에서 문대한·김예린 2인의 하루설계 팀을 확인할 수 있음.

2026.11.08 확인: 공개 데모 서버는 응답하지만 AI 사용 가능 상태는 false. 현재는 기록 데모를 볼 수 있으며 새로운 실제 AI 실행은 제공되지 않는 상태. 아래 링크는 이 한계를 확인한 뒤 체험하는 용도.

하루설계 데모 열기 (기록 재생)

사용자 비교 실험과 시간표 직접 편집은 아직 없음. 고도화 버전의 실제 AI 실행 검증은 로컬 기록이며, 고도화 Azure 배포본에서의 실제 AI 호출 검증과 구분함.
