문제와 사용자

사용자 상황 여러 증권사의 리포트와 컨센서스를 서비스에서 비교·활용하려는 사용자.

증권사마다 문서 형식이 달라 리포트와 컨센서스를 모아 서비스에서 쓰는 과정이 필요했습니다.

본인 역할과 협업

5인 팀의 팀장·PM으로 기획, 일정·업무 배분, 멘토 소통을 맡았습니다. FnGuide·WiseReport 등 리포트 소스의 기본 수집 코드는 직접 작성했습니다.

PDF 파싱 대안은 담당 팀원과 멘토와 함께 검토했습니다. 웹서비스 배포는 팀의 결과입니다.

선택과 이유

컨센서스 수집 코드를 작성했습니다. PDF 본문·표·이미지의 처리 문제는 담당 팀원과 멘토에게 공유하고 대안을 검토했습니다.

수집과 파싱을 나눠 맡고, PDF가 잘 읽히지 않는 원인을 본문·표·이미지로 구분해 검토했습니다. 문서의 일부가 누락되면 화면에 필요한 분석 정보를 만들기 어렵기 때문입니다.

구현·진행 과정

  1. 업무와 일정

    팀의 일정과 담당 업무를 나누고 멘토와 진행 상황을 공유했습니다.

  2. 리포트 수집

    FnGuide의 전일 수집·날짜 범위 백필, WiseReport의 날짜 필터·Excel 내려받기를 다룬 기본 수집 코드를 작성했습니다.

  3. PDF 처리 검토

    본문·표·이미지의 처리 문제를 나눠 대안을 검토했습니다. 로컬 코드에는 첫 페이지를 분리해 Docling으로 파싱하는 시도가 남아 있습니다.

  4. 서비스 화면

    대시보드·D-Day·D+1·상세 화면을 팀이 구성했습니다. 별도 Flask 목업의 인증·DB는 시연용입니다.

확인한 결과

5인팀 규모 · 본인 역할은 팀장과 PM

컨센서스 수집 코드와 화면 목업이 남아 있으며, 팀은 웹서비스를 배포했습니다.

한계와 다음 확인

실제 사용자 테스트는 진행하지 못했습니다. 이용자 수와 투자 효과는 측정 결과가 없습니다.
