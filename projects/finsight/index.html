이 사례에서 읽을 내용

배경과 목적진행한 일과정결과물성장과 결과직무 기여 역량다음 확인

배경과 목적

증권사마다 문서 형식이 달라, 화면에 쓸 정보를 얻으려면 리포트·컨센서스를 모으는 일과 PDF 내용을 읽어내는 일이 모두 필요했습니다. 팀은 수집과 파싱을 나눠 맡았습니다.

PDF 본문이나 표·이미지의 내용이 빠지면 화면에 보여 줄 정보도 부족해집니다. 그래서 막힌 문제를 한 덩어리로 두지 않고 본문·표·이미지 유형으로 나눠 담당 팀원과 멘토에게 공유했습니다. 유형을 나누면 무엇을 논의해야 하는지 담당 팀원과 공유하기 쉬워집니다.

검토한 대안의 예: 로컬 코드에 첫 페이지를 분리해 Docling으로 파싱한 시도가 남아 있습니다. 대안 검토의 한 예이며, 작성자와 최종 채택 여부는 확인되지 않았습니다.

배경
증권사 리포트와 컨센서스를 한곳에서 보는 2025년 5인 팀 프로젝트입니다.
문제
증권사별 PDF 형식 차이로 본문·표·이미지 추출에 문제가 생겼습니다.
핵심
수집과 파싱을 나눠 맡고, 파싱 문제를 유형별로 공유했습니다.
해결 방향과 행동
기본 수집 코드를 작성하고 담당 팀원·멘토와 처리 대안을 검토했습니다.

담당과 협업

2025년 5인 팀 팀장·PM, 기본 수집 코드 직접 작성. 화면·배포는 팀 결과이며 2026년 AI 협업 ETL은 별도 후속 활동입니다.

기록에 남은 행동

팀장·PM으로서

  • 팀 일정을 조율하고 업무를 나눴으며, 멘토에게 진행 상황을 공유했습니다.
  • PDF 처리 문제를 본문·표·이미지로 나눠 담당 팀원·멘토와 대안을 검토했습니다.

직접 작성한 수집 코드

  • FnGuide 전일 수집과 날짜 범위 백필, WiseReport 날짜 필터와 Excel 내려받기를 다루는 기본 코드를 작성했습니다. 2025년 본인 계정의 추가·수정 이력으로 확인됩니다.
  • 전일 수집은 새로 나온 자료를, 날짜 범위 백필은 지난 기간 자료를 다룹니다.

판단과 확인 범위

본문·표·이미지로 문제를 나누니 담당 팀원·멘토에게 논의할 대상을 구체적으로 전달할 수 있었습니다. 첫 페이지 Docling 시도의 작성자와 최종 채택은 별도 확인이 필요합니다.

성장과 확인한 결과

팀이 웹서비스를 배포했고 본인이 작성한 기본 수집 코드 이력이 남아 있습니다. 실사용 테스트·이용자 수·투자 효과는 측정하지 못했습니다.

직무에 기여할 역량

일정·업무 배분과 멘토 소통, 처리 문제의 유형별 정리는 구현 제약을 팀과 검토하는 PM 업무의 근거입니다.

보완할 근거와 다음 확인

  • 측정하지 않음: 실사용 테스트를 하지 못했고 이용자 수, 투자 효과, 수익률을 측정하지 않았습니다.
  • 확정하지 않음: 전체 파싱의 개인 수행, Docling 시도의 작성자와 최종 채택, 칸반 작성자, 프로젝트 종료 월.
  • 보완할 자료: PDF 유형별 처리 결과 예시, 배포 화면 캡처, 멘토 검토 기록, 역할표·일정표 원본.
