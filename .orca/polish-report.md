# Polish 보고서 (2026-10-15, 브랜치 `polish`)

main에는 push하지 않았다. 모든 변경은 `polish` 브랜치 커밋에 있다. `git log main..polish` 로 확인한다.

## 1. 바뀐 것

### 채용 담당자 관점 점검
- 깨진 내부 링크: 0건 (전체 HTML의 href/src 검사).
- 메타·OG: 공개 페이지 모두 title, description, og:title, og:image, canonical, viewport, lang=ko를 갖췄다. `briefs/*`는 noindex 리다이렉트라 제외했다.
- 모바일(375px): 주요 11개 페이지 가로 넘침 0건, alt 없는 이미지 0건, h1은 각 1개.
- **수정** 모바일 첫 화면: 증명사진이 화면 40%를 차지해 헤드라인이 아래로 밀렸다. 640px 이하에서 사진을 84px 썸네일로 줄여 이름 옆에 붙였다. 이제 첫 화면에 직무, 헤드라인, 세 사례 요약, 버튼, 대표 사례 제목까지 보인다 (`home.css`).
- **수정** 문체: 한다체 본문에 존댓말 1인칭(저는, 제가, 제 이름)이 섞여 있었다. 웹 5개 페이지와 포트폴리오 슬라이드 18곳을 나는, 내가, 내로 바꿨다.
- 수정한 페이지의 「최종 수정」 날짜를 2026.10.15로 올렸다.

### 대표 사례 배운 점
- 온통청년, NCA, Dear Log 페이지 끝에 「배운 점」 섹션을 넣었다. 모든 문장 앞에 [초안] 표시가 있다.
- 포트폴리오 PDF에 같은 문구로 「세 사례에서 배운 것」 슬라이드를 넣었다 (15쪽, 마무리 앞). PDF는 15쪽에서 16쪽이 됐다.

### 이력서
- 소개 칸에 직무 맞춤 요약 3문장을 넣었다 (PDF·DOCX 표, 웹 상단). 내용은 기존 페이지 사실만 썼다.
- 핵심 역량을 PDF·DOCX는 2개, 웹은 3개로 서로 달랐던 것을 4개로 통일하고 근거를 사례 단위로 붙였다.
  1. 범위와 기준 정의: 온통청년 시설 범위 제안, 양주 좌석 0석과 정보 없음 구분
  2. 공개 범위 판단: NCA 점수 공개 중단과 승인 조건 4가지, Dear Log 가입 닫기와 서버 분리
  3. 직접 써 보고 대조: Dear Log 수정 요청 10건, 양주 매핑 6건 대조
  4. 팀 일정과 문제 조율: 온통청년 팀장, Finsight PDF 처리 문제 검토
- 이전 PDF에서 「응답 기준 작성」 근거로 쓰던 「Dear Log 수정 요청 10건」은 응답 기준과 맞지 않아 3번 역량 근거로 옮겼다.
- 2쪽 유지: 요약을 넣자 3쪽이 돼서 표 칸 여백(4pt→3.2pt)과 줄 간격(1.5→1.45)을 줄였다. resume.pdf와 resume.docx(LibreOffice 변환 기준) 모두 2쪽이다.

### 포트폴리오 PDF
- 흐름은 표지, 세 사례 요약, 사례 3개(각 4쪽), 배운 점, 추가 경험과 연락처 순서다. 16쪽 모두 넘침 0건(브라우저 측정)이고 렌더링 이미지로도 확인했다.
- 2쪽 요약 슬라이드만 흰 배경인데, `.op` 클래스로 일부러 넣은 디자인이라 그대로 두었다.
